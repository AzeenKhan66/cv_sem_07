# LAB 05: HOG-Based Industrial Defect Detection

A computer vision prototype that inspects steel surface images and decides whether a product should be accepted or rejected. It uses Histogram of Oriented Gradients (HOG) features and classical machine-learning classifiers.

Pipeline:

```
Image → Preprocessing → HOG Feature Extraction → ML Classifier → Defective / Non-Defective decision
```

## Contents

- `LAB05_HOG_Defect_Detection.ipynb`: the full Colab notebook
- `realtime_inspect.py`: webcam prototype (bonus), generated by the last notebook cell
- `hog_defect_model.joblib`: saved model, produced when the notebook runs

## Dataset

NEU Surface Defect Database (NEU-DET), steel surfaces, via Kaggle:
`sovitrath/neu-steel-surface-defect-detect-trainvalid-split`

The dataset has six defect classes: crazing, inclusion, patches, pitted surface, rolled-in scale and scratches.

**Note:** NEU-DET contains only defective surfaces. A Non-Defective class needs defect-free images. Set `NORMAL_SOURCE` in section 4 of the notebook to a folder of defect-free images to enable the binary task. Without it, the notebook runs six-class defect classification and reports the defect type.

- numpy, pandas, matplotlib

## How to run

1. Open `LAB05_HOG_Defect_Detection.ipynb` in Google Colab (File → Upload notebook).
2. Run all cells in order. Section 1 downloads the dataset with `kagglehub`.
3. Check the printed folder layout and class counts in section 3. If labels are empty, adjust `label_from_path`.
4. Optional: set `NORMAL_SOURCE` for the binary task.
5. Read the results in sections 7–11.
6. Download `hog_defect_model.joblib` for the webcam prototype.

## Method

- **Preprocessing:** grayscale conversion, resize to 128×128 (INTER_AREA).
- **HOG features:** orientations, cell size and block size set in section 5 (default: 9 orientations, 8×8 cells, 2×2 blocks, L2-Hys normalization).
- **Classifiers:** HOG + SVM (RBF kernel, standardized features) and HOG + Random Forest (300 trees).
- **Split:** stratified 75/25 train/test, fixed seed 42.
- **Metrics:** accuracy, precision, recall, F1 (macro across classes; binary when a Normal class exists), confusion matrix and classification report.

## Experiments

- **HOG parameter sweep:** cell sizes 4, 8, 16 × orientations 6, 9, 12, with an SVM retrained for each combination. Results are shown as a Macro F1 heatmap.
- **Robustness:** the trained model is tested on perturbed test images only:
  - brightness (×0.6 and ×1.4)
  - Gaussian noise (σ = 20)
  - rotation (15°)
  - Gaussian blur (5×5)

  The change in accuracy and F1 is reported against the clean baseline.

## Quality-control output

The decision module prints the result in this format:

```
PRODUCT INSPECTION RESULT
Prediction: DEFECTIVE
Confidence: XX%
Action: REJECT PRODUCT
```

or

```
PRODUCT INSPECTION RESULT
Prediction: NON-DEFECTIVE
Confidence: XX%
Action: ACCEPT PRODUCT
```

Without a defect-free class, every image is reported as DEFECTIVE, and the predicted defect type is shown.

## Webcam prototype (bonus)

After downloading `hog_defect_model.joblib` to the same folder as `realtime_inspect.py`:

```
python realtime_inspect.py
```

The script shows a live camera feed with a PASS or DEFECTIVE label. Press `q` to quit. The model was trained on steel-surface images, so use it on a steel surface under fixed lighting. Results on a webcam feed of other objects will not be meaningful.

## Limitations

- Results depend on the labelling and split used. Check that the same image does not appear in both train and test.
- Without defect-free images, the binary Defective / Non-Defective task cannot be evaluated.
- HOG is sensitive to lighting and contrast. The robustness tests show how much accuracy drops under the conditions tested.
- The webcam prototype has not been tested on a production line.
